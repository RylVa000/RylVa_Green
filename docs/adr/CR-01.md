Change Request (CR-01): Otomatisasi Visibilitas Produk & Label Edisi Terbatas
1. Perubahan Skema Basis Data
Entitas Produk pada Bagian 5 (Model Data Konseptual) diperluas dengan menambahkan tiga kolom baru untuk mendukung otomasi tanpa memerlukan intervensi manual Admin setiap pergantian musim:

periode_mulai_tayang (Tipe: DATETIME, Boleh NULL): Waktu spesifik kapan produk mulai dipublikasikan ke antarmuka pelanggan.

periode_akhir_tayang (Tipe: DATETIME, Boleh NULL): Waktu spesifik kapan produk otomatis ditarik (disembunyikan) dari katalog.

label_promosi (Tipe: VARCHAR(50), Boleh NULL): Teks kustom yang akan dirender sebagai badge/ribbon pada foto produk (Contoh: "Limited Edition", "Spring Collection", "Eksklusif").

2. Penambahan Aturan Bisnis Baru (Bagian 18 - Business Rules)

BR-35 (Kondisi Tayang Katalog): Produk hanya akan ditampilkan di Halaman Beranda, Katalog, dan Hasil Pencarian jika memenuhi ketiga syarat absolut berikut:

Atribut status = 'Aktif'.

Waktu server lokal (WIB) lebih besar atau sama dengan periode_mulai_tayang (jika kolom tidak bernilai NULL).

Waktu server lokal (WIB) lebih kecil dari periode_akhir_tayang (jika kolom tidak bernilai NULL).

BR-36 (Prioritas Status Habis): Jika perhitungan stok dari BukuBesarStok menyentuh angka 0, maka label_promosi bawaan (misal: "Limited Edition") akan diabaikan oleh frontend, dan antarmuka wajib merender badge dengan warna abu-abu bertuliskan "Habis" secara hardcode, sementara tombol "Tambah ke Keranjang" dikunci (disabled).

3. Implementasi Logika Backend (PHP Native)
Query SQL pemanggilan katalog utama akan dimodifikasi menjadi seperti ini untuk menjamin performa dan mengurangi beban logika di sisi frontend (JavaScript):

SQL
SELECT id, nama, harga, label_promosi 
FROM Produk 
WHERE status = 'Aktif' 
  AND (periode_mulai_tayang IS NULL OR periode_mulai_tayang <= NOW()) 
  AND (periode_akhir_tayang IS NULL OR periode_akhir_tayang > NOW());
