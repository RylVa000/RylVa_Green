# Backlog implementasi setelah audit backend

Disusun 21 November 2026 dari kode aktual, skema uji dan baseline v2.6. Ini urutan pekerjaan proyek; bukan pengingat otomatis atau perubahan aturan bisnis. Rencana kalender tetap pada [jadwal](implementation-schedule.md).

| Urutan | Tahap | Pekerjaan konkret | Berkas/modul utama | Kriteria penerimaan / prasyarat |
| --- | --- | --- | --- | --- |
| 1 | M0 | Jalankan workflow yang tersedia pada GitHub dan selesaikan temuan runner nyata. | `.github/workflows/backend-ci.yml`, `tools/testing/` | Push/commit diminta pengguna; matrix PHP 8.2/8.3, MySQL, lint, audit dan tes hijau. Perintah setara sudah lulus lokal. |
| 2 | M0 | Lanjutkan verifikasi database/ekstensi online dan latihan pemulihan sebelum gerbang produksi. | `deploy/`, `tools/testing/verify-ftp-staging.cjs`, `verify-query-navigation.cjs` | Staging UI/fondasi sudah dipasang: HTTPS, 54 dokumen, 9 kelompok HTTP/render dan 10 kelompok navigasi lulus. Mode query mengatasi larangan rewrite. Rincian di coverage hosting online; database hosting belum diubah/diuji. |
| 3 | M1 | Hash kata sandi, penyimpanan sesi database, cookie aman, CSRF dan pembatasan percobaan server. | `Infrastructure/Security/`, `Http/Middleware/`, `sesi_login`, `batas_laju_permintaan` | Pisahkan sesi pelanggan/staf; uji fiksasi/revokasi/expiry, token CSRF hilang/salah dan rate limit. Ikuti parameter baseline; periksa konflik P-31/RL-02 sebelum menetapkan pemetaan. |
| 4 | M1 | Registrasi/login/logout pelanggan, verifikasi email dan pemulihan tanpa enumerasi akun. | `Http/Controllers/Auth/`, `kode_verifikasi`, `antrean_keluar` | Respons generik sesuai baseline; kode/token dibatasi dan sekali pakai; penyampaian email memerlukan konfigurasi SMTP. Input tidak hilang saat kegagalan yang bisa dipulihkan. |
| 5 | M1 | Login staf, TOTP MFA, kode pemulihan, otorisasi peran/kepemilikan dan autentikasi ulang. | `TotpMfaService`, `SecretBoxCrypto`, middleware staf/MFA/role | Tindakan tidak sah ditolak server; rahasia terenkripsi; isolasi akun pelanggan/staf dan dua pihak untuk tindakan terkait dipenuhi. |
| 6 | M1 | Hubungkan Profil Akun, identitas eksternal dan persetujuan yang memiliki versi. | Akun pelanggan, `identitas_eksternal`, `log_audit` | Kebijakan publik final dan metadata persetujuan tersedia; OAuth perlu client/redirect nyata. Jangan menganggap badge UI sebagai bukti verifikasi server. |
| 7 | M2 | Katalog/kategori/atribut/varian/panduan dari sumber database yang sama untuk publik dan staf. | Controller katalog, repository, `produk`, `varian_produk`, kategori/atribut | Filter/sort/pagination tervalidasi; produk tidak aktif ditolak; admin CRUD dan izin benar. Data awal dump tetap fixture sampai dikonfirmasi pemilik. |
| 8 | M2 | Satu layanan transaksi stok untuk saldo lokasi, counter ringkasan dan buku besar. | `Domain/Stock/Services/`, `TransactionManager`, tabel saldo/mutasi | Uji stok terakhir dengan koneksi serentak; tidak ada saldo negatif/komit ganda. Tangani varian NULL dan cek pasangan produk–varian; penguatan skema memerlukan migrasi bernomor. |
| 9 | M2 | Resep, kebutuhan opsi/snapshot bahan, batch/FEFO dan paket berkebun. | `Domain/BouquetCustomization/`, `FefoBatchAllocatorService`, tabel resep/komponen | Bahan tidak dihitung dua kali; stok jual dan bahan terpisah; alokasi komponen atomik dan pembatalan memulihkan sesuai pemicu sah. |
| 10 | M3 | Keranjang tamu/akun dan penggabungan, Wishlist serta validasi ulang server. | Controller Cart/Wishlist, tabel keranjang/daftar keinginan | Identitas produk/varian, kuantitas dan harga server benar; konflik dan barang hilang memiliki pemulihan; otorisasi kepemilikan diuji. |
| 11 | M3 | Checkout dengan alamat, quote vendor, tanggal/slot dan pembuatan pesanan idempoten. | Checkout, adapter kurir, snapshot pesanan/reservasi | Vendor/area siap; aturan mudah layu/campuran divalidasi; perubahan biaya memerlukan persetujuan ulang; retry tidak membuat pesanan ganda. |
| 12 | M4 | Adapter pembayaran nyata, webhook terverifikasi, state machine, COD dan rekonsiliasi. | `VendorPaymentGatewayAdapter`, `PaymentConfirmationAlgorithm`, `Domain/Orders/StateMachine/` | Vendor sandbox tersedia; uji signature/API mismatch, replay, nominal lebih/kurang/ganda, kedaluwarsa dan commit sebelum acknowledgment. Mock M0 bukan kelulusan tes vendor. |

M5–M8 tetap mengikuti jadwal: pemenuhan/pengiriman, pembatalan/refund/komplain, notifikasi/pengerasan, lalu UAT dan keputusan rilis. Belum ada percepatan estimasi atau perubahan cakupan karena fondasi lokal selesai lebih awal.

Setiap baris ditutup dengan hasil yang dijalankan, izin/validasi server, pemulihan kegagalan, bukti tes dan dokumentasi. Keberadaan file, mock atau halaman pratinjau tidak cukup untuk menandai modul bisnis selesai.
